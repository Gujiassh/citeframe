# Compaction foundation

`packages/memory-service` provides neutral context-compaction types, complete-unit packing, bounded summaries, interval rendering, source guards, request accounting, and transactional checkpoint storage. These components are not connected to the application Chat or Research dispatch paths. They do not provide native final-answer publication, a complete tool loop, SSE presentation, or automatic application resume.

## Context and summaries

Context owners identify the workspace, actor, and Chat execution or Research attempt. Coverage contains explicit versioned sources or complete archived tool groups. Tool calls and their results remain ordered complete units. Current-question and other protected anchors retain their original chronological positions; a checkpoint cannot hide a protected anchor. Recent and uncompressed units stay in order around replaced intervals.

The gate counts the complete serialized request against an explicit connection, counter identity, output reserve, input ceiling, and safety margin. Policy defines soft and target watermarks, minimum new history and gain, chunk-call and unit limits. Summary and merge calls have separate bounded purposes, time/call limits, and accounting. A candidate must validate its source references, typed facts, conditions, quantities, conflicts, and unresolved work, then show sufficient measured gain before adoption. Summary text remains attributed task data and creates no new evidence authority. Structural and omission checks do not establish live-model semantic quality.

Persisted intervals record their original boundaries and input/profile provenance. A later checkpoint can extend or add compatible intervals while preserving prior protected anchors and coverage. Restart reconstruction validates the parent chain, saved call/result state, original capture, profile, source support, and interval transitions before rendering the next request. Missing or mismatched metadata fails explicitly. Chain traversal is bounded by the episode policy and an aggregate 1 MiB rendering-metadata limit. An unchanged no-progress boundary does not cause repeated summary attempts.

## Sources and atomic storage

Shared-source readers admit only registered `chat_message` and `research_evidence` sources. Chat bodies must belong to the permitted ancestry and retain the captured native revision; Research evidence must remain within its frozen execution/evidence snapshot and current asset/source scope. Capture and send/adoption rechecks retain workspace membership, owner/lease, cancellation, deadline, native state, source version, and coverage guards. A source descriptor or summary reference alone grants no read permission.

Private instructions, including the requester's own, remain excluded from shared Chat/Research prompts, tools, summaries, checkpoints, planning, and derived outputs. Existing owner-private persistence remains separate. Shared compaction does not promote private instructions into workspace sources. See [private instruction persistence](private-instructions.md).

The repository requires PostgreSQL with `READ COMMITTED`, row locks, bounded transaction/statement/lock timeouts, and full-transaction rollback on contention. Guarded contention permits at most two attempts. Snapshot, ordered coverage, source/checkpoint/tool dependencies, and native context-pointer compare-and-swap commit in one transaction. A failed candidate or competing context change cannot advance the pointer. Reconciliation checks a committed operation identity and its provenance; an uncommitted summary cannot become an adopted checkpoint. External object or provider IO occurs outside these database lock scopes and is followed by guarded revalidation.

Migration `u5c6d7e8f9a0` directly follows `t4b5c6d7e8f9`. It adds Chat memory executions, call/snapshot/coverage storage, native context pointers and row-local Chat revision stamps, and extends source/use constraints for shared task data. PostgreSQL constraints and triggers protect immutable identities, scope, coverage, and pointer relationships. Native revision stamps detect post-capture mutation and recreation; they do not provide a complete event history or freeze the graph between execution registration and its first capture. Downgrade refuses retained compaction data before removing its structures.

## Send accounting and lifecycle boundaries

Neutral dispatch prepares and revalidates the captured request, reserves its call/accounting identity, archives and reads back the exact request, and marks it sent before generation. Summary calls use the same bounded journal path. Research accounting binds native provider-call and budget-ledger identities; settlement preserves reported versus unknown usage. A retry does not erase prior calls or reset the cumulative execution budget. Ambiguous sent results require reconciliation and do not authorize an automatic resend.

Summary collection closes abandoned closable iterators, retains the primary failure if cleanup also fails, and uses stable error codes. Cancellation checks are cooperative around preparation, send, collection, and adoption; they do not actively interrupt a blocked provider read. Caller-owned transport lifetime and timeouts still apply. See [provider adapters and turn helpers](provider-foundation.md).

Native final-answer authority and waiting/resume eligibility remain integration boundaries. A settled main-call receipt does not establish that the call produced the current final answer rather than an intermediate tool turn. Core Chat guards admit `prepared`, `running`, and `waiting_context`; this admission does not make `waiting_context` a fresh-send prohibition or supply a trusted changed-condition record for resume. Application activation requires explicit terminal-answer binding and separate read/checkpoint versus fresh-send eligibility, together with the native authorization, source, budget, recovery, and publication contracts.
