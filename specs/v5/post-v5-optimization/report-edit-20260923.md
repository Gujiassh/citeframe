# Final report editing — 2026-09-23

## Scope and contract

Completed research runs with a user-visible final Markdown artifact expose a separate server-persisted user edition. The generated artifact, its object bytes, claim verification, and evidence links remain unchanged. The user edition is always labeled `unverified`; the evidence list in the run panel is labeled `Original evidence` and continues to refer only to the generated artifact.

- `GET /v1/workspaces/{workspace_id}/research-runs/{run_id}/report-edit`: current workspace members may read. Returns the original artifact ID/hash and user-edition version (`0` and `null` Markdown before the first save).
- `PUT` at the same path: only the run creator with current workspace membership may save a completed final report. Request `{expectedVersion, markdown, originalArtifactId, originalSha256}`. Whitespace-only text, text over 200,000 characters, and UTF-8 content over 1 MB are rejected. A stale version returns `409 report_edit_version_conflict` with `currentVersion` and makes no write.
- `research_report_edits` holds one row per run: version, last editor, original artifact ID/hash, Markdown, and update timestamp. Revision `o9c0d1e2f3a4` follows `n8b9c0d1e2f3`. The save serializes through a research-run row lock before version comparison. Every read/save checks generated artifact bytes against its stored size/hash; changed or unavailable originals cannot be silently rebound to a user edition.
- Browser requests use a dedicated same-origin Next route. The original/user-edited tabs, edit/save/cancel, loading/retry, and explicit two-tab conflict choices are owned by the report editor component. Its keyed lifetime and abort/epoch checks discard stale GET/PUT responses after run selection changes or unmount. A 409 keeps the local draft and requires an explicit choice before saving against the newer version.

## First-save original binding

The client sends the original ID and SHA-256 it actually displayed with every PUT, including version zero. Under the run lock the service refreshes and share-locks the current artifact, validates its bytes, and compares the client base before creating or changing an edition. A mismatch returns `409 report_edit_base_conflict` with no edition write. Missing base fields return 422. Edition version CAS continues to reject stale subsequent saves. The editor keeps the draft on base conflicts and asks the user to copy it before reloading; it does not silently rebase. API coverage now includes replacement between initial GET and first PUT and an incorrect original ID. The browser route-fixture suite has five cases, including the first-save conflict and preserved draft.
