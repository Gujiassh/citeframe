Provide real history discovery and exact original-source reads, pinned to versions/ranges, authorized for **every possible reader of the destination output**. Reuse memory_sources and memory_uses. Full content-unit/artifact exact-source obligations and actual hybrid retrieval remain required follow-on deliverables; this subset cannot close shared-history/index scope.

## 4. Concrete native issuer and shared-consumer delta

History authorization is issued inside the existing PostgreSQL repository transaction, never accepted as a caller-constructed DTO or generic proof port. #43 owns the issuer and its consumers. NEW history service modules receive a transaction-local HistorySession from that issuer and cannot register it for later use. It contains the live SQLAlchemy Session/transaction identity, validated native owner, locked frozen snapshot IDs/version/hash, concrete scope projection, native source metadata and an internal issuance marker. Constructing a lookalike, deserializing a cursor or replaying an earlier transaction's object does not authorize hydration.

## 5. Exact reference, range and native version

Reuse SourceReference(source_id,version>=1,sha256 hex64). One serializer maps to design JSON sourceId/sourceVersion/contentSha256. Proposed SourceSelection={reference,span:null|TextSpan|LocatorSpan}; it contains no duplicate identity triple.

TextSpan: kind=text, Unicode code-point start/end, 0<=start<end<=whole exact body length. Not byte or UTF-16 offsets. Empty originals use span=null. LocatorSpan: kind=locator, exact pinned locatorId; initial unit adapter permits only its source_locator_id, not arbitrary neighboring locators.

Hash exact UTF-8 of the named whole text. Accepted UTF-8 artifact hashes equal original stored-byte hashes; preserve BOM/newlines/Unicode. Binary/unsupported encoding has no text projection; return source_version_unavailable with only an independently authorized native route where applicable.

On the first page only, before/after (code points, each0..2000) expand the selected text/locator interval once: windowStart=max(0,start-before), windowEnd=min(bodyLength,end+after). span=null fixes [0,bodyLength); before/after must be zero in that case. This terminal window never expands on continuation. A cursor request omits before/after and span or must repeat the exact first-page selection; any conflicting value rejects. returnedRange=[nextStart,pageEnd); nextStart advances to pageEnd. At windowEnd return nextCursor=null,truncated=false; empty original returns one empty terminal page. A nonterminal zero-length page is forbidden.

Counting consumes the actual accepted TokenCounter.count(GenerationRequest,ModelConnectionSnapshot), through #43 policy.count_request validation, not a string-only substitute. Composition supplies the frozen connection snapshot plus CounterIdentity and actual next-main GenerationRequest framing. For each candidate page construct the exact complete assistant tool-call batch + ordered tool-result GenerationMessages, including the serialized source/provenance/range/cursor envelope, existing prompt/messages/tools/max_output_tokens and all sibling results. Count this full candidate and a baseline with the identical result envelope but empty content; enforce max(0,candidate.tokens-baseline.tokens)<=2000 and the full candidate's remaining main context capacity. All framing overhead is charged in the full-request check. Each page additionally caps content at16000 code points. Standalone management reads use a pinned, versioned single complete tool-pair request template and the same configured connection/counter; they never claim to budget a later task request.

**Stable continuation authority and per-dispatch budget are separate.** Signed read cursor binds only cursor/paging policy version, authenticated actor/workspace/native owner, frozen history-policy/scope authority, original selection, source ID/version/hash/bodyLength, fixed windowStart/windowEnd,nextStart and original expiry. It contains neither tool-call ID, current GenerationRequest hash/base-message hash, context_version, renewable lease token nor connection/counter fingerprint. Those values legitimately change on later tool turns. The new native issuer must still prove current lease/lifecycle/readers and the cursor's stable scope; a cursor itself grants no authority.

For EACH page, composition supplies the CURRENT complete next-dispatch GenerationRequest and CURRENT authorized ModelConnectionSnapshot/CounterIdentity. A fresh per-page countingProfileSha256 hashes connection config_fingerprint/protocol/model/capacities, counter_id/counter_version/mode/config_fingerprint and current framing schema/max_output_tokens (excluding credentials). Record current exact fully assembled request SHA-256 separately. count_request validates the actual TokenCount identity; exact/approved estimated modes are labeled truthfully. A different later tool ID, prompt context, request hash or valid model budget changes this page's fit; it does not invalidate source continuation or send it back to page1. An unauthorized provider/profile fails CURRENT native dispatch-policy validation; the unchanged cursor can be retried after fixing that context, without re-expanding its window.

Each returned page carries its own internal page-budget record: current tool-call ID, returnedRange, counting profile/count identity/mode, counted complete-request SHA-256 and token result. ToolArchive hashes/archives the exact result group through its existing result path. The existing request archive/journal records the exact final GenerationRequest hash before dispatch; equality with the counted candidate is required. If sibling results or framing change after initial page fit, reassemble/recount before reservation/send, shrinking the not-yet-issued page if necessary. No counted-request cache or page1 hash authorizes another turn. Do not put budget records into stable cursor authority.

Tokenization need not be monotonic in prefix length. Start at the cursor's nextStart, choose a bounded prefix ending at or before windowEnd, count the complete request, shrink/recount on overflow without assuming binary-search monotonicity, and emit only a fitting prefix. If one code point plus current full framing cannot fit, return context_capacity_too_small without consuming or advancing the cursor; task compaction/rebudgeting may retry that SAME cursor. No nonterminal zero-length result or automatic restart. Reauthorize exact source/readers after counting and before archive adoption.

Cursor serialization freezes expiry/window and deterministic signature fields before counting, so the counted result is the emitted result. Final returnedRange/cursor bytes are included in the current complete request count; no self-referential request hash is embedded into that counted payload (budget hash metadata stays in the journal). An exact same-tool idempotent replay returns its archived page after fresh permission checks. A new tool invocation with the same input cursor may fit a different positive-length prefix under its current budget; it must start at the same nextStart and cannot jump or expand. Only the returned nextCursor advances to that page's end. Each accepted continuation strictly advances until the fixed terminal window ends. Full-body pages reconstruct the original; bounded reads reconstruct their fixed expanded window.


Direct read needs a registered ref; search supplies refs. Native-to-reference registration is a trusted composition operation, not a public arbitrary-object lookup.

## 8. Workspace corpus, native events and atomic suppression

### 8.1 Corpus versus query projection

Each (workspace,source_kind) manifest covers the entire eligible workspace-native corpus under corpus_scope='workspace', with its exact source set including zero-chunk originals. ### 8.2 Note monotonic identity and event matrix

Proposed migration adds notes.history_revision bigint NOT NULL CHECK>0 and a PostgreSQL noncycling bigint sequence dedicated to this native stamp. Backfill assigns each existing note a fresh sequence value. BEFORE INSERT/UPDATE overrides client-assigned stamps: INSERT always nextval; any change to native identity/body/title/archive/creator/editor/pinned/created_at/updated_at tuple gets nextval; exact no-op preserves OLD stamp. Workspace/id changes are prohibited for already registered sources rather than moving authority. Sequence gaps from rollbacks are valid. Sequence is not reset on rollback/backfill rerun and a populated downgrade refuses to discard it. Delete/reinsert of the same UUID gets a larger fresh stamp; retained registry tombstones cannot be reused. Overflow fails mutation, never wraps.

source_version equals history_revision; register_exact requires equality with the locked native stamp and exact native tuple/hash. No max(registry.version)+1 allocator, timestamp-derived version or hash-only identity. A->B->A changes, including multiple updates inside one transaction with identical updated_at, advance stamp each time; a new registration has a new ref even if body bytes return to A. Archived/restored notes acquire new stamps and never restore a formerly unavailable source row to current.

### 8.3 Single transaction invalidation across the accepted graph

One owner-approved database invalidation routine is called by narrow native triggers and guarded service mutations. Transaction order:
1. Lock workspace, native owning rows, source registrations in stable ID order, affected consumers, then index manifests/entries. Before changing native/source state, execute the pending-insert constraint barrier specified below. Application native writers acquire workspace guard before DML; trigger-only entry that cannot establish lock order fails/rolls back rather than committing partial invalidation. SQL bypass tests must exercise this path.
2. Apply native stamp/mutation; mark current/superseded source rows stale/unavailable or all versions deleted for native deletion. Deleted source.content_sha256=NULL; strict kind-specific native tuple hash fields become JSON null only in the deleted branch, immutable identity/version keys retained.
3. Compute recursive reverse closure from memory_uses.source_id through each consumer; continue through existing used_snapshot_id and used_tool_call_id references to those snapshot/tool-result consumers. Preserve existing direct source/snapshot/tool-result edges and flattened leaves. Current #43 has consumer_revision_id for P1a source support but NO used_revision_id or observed_head_version dependency field. Do not add, query or activate either in this slice; future design4.4 revision dependencies require their own reviewed migration/consumer contract. Include both call input/result parts. No “raw leaf still exists” shortcut; no partial fanout commit. If bounded closure/lock limits are exceeded, abort the native mutation with a retryable safe conflict; asynchronous fanout is not the correctness barrier.
4. Set affected TaskMemorySnapshot.status=invalidated and invalidated_at, and MemoryCall.result_state=invalidated where a valid/absent future result could otherwise be adopted. Mark reserved/sent calls' capture unusable through the same dependency closure/fingerprint; retain accounting state and allow neutral settlement. No refund or claim of recalling an already sent request. Dispatch linearizes at #43 mark_sent under those guards: invalidation committed before that point blocks send; invalidation afterward suppresses result adoption/reuse while normal usage settlement completes. All pre-send/adoption/replay paths revalidate current dependencies. New result commit after invalidation must fail CAS, not overwrite invalidated state with valid.
5. Retire affected corpus manifests; on native deletion synchronously delete all source index chunks/vectors across generations. For privacy erasure, affected checkpoint summary=NULL,status=erased,erased_at set; result_state=erased and no body replay. Object archives may require existing retention cleanup, but authorization/result predicates suppress every fetch immediately; do not claim remote byte deletion is atomic with PostgreSQL.
6. Commit native mutation, source metadata, derived suppression and index retirement together. A failed step rolls back all. Old invalidated/erased objects cannot transition back to valid/committed. Rebuild creates a new object only from surviving complete support under fresh authorization.

**Actual trigger timing and required insert/invalidate protocol:** compaction_snapshot_complete is a DEFERRABLE INITIALLY DEFERRED constraint trigger AFTER INSERT on task_memory_snapshots. compaction_coverage_complete is deferred AFTER INSERT/UPDATE/DELETE on task_memory_coverage; its immutable coverage guard separately rejects edits to retained coverage. Updating an already committed snapshot's status alone does not enqueue snapshot completeness.

A pending INSERT is different: INSERT a snapshot/coverage, then invalidate or erase a source in the SAME transaction leaves queued insert checks that execute against changed source state at commit. Do not solve this by skipping completeness whenever current status is invalidated. Before any native/source invalidation, the mutation entry/BEFORE native-row trigger executes SET CONSTRAINTS compaction_snapshot_complete,compaction_coverage_complete,compaction_use_scope,compaction_chat_pointer,compaction_research_pointer IMMEDIATE while the pre-mutation native/source state still exists. This discharges pending snapshot/coverage/use/native-pointer checks, including original hashes, exact source scope, contiguous coverage, parent extension and native pointer. A malformed/incomplete new snapshot cannot be laundered by immediate invalidation: it fails and the transaction rolls back.

After successful barrier, perform the native change and monotonic suppression in the same transaction. Keep these constraints immediate for the remainder of this mutation transaction; no new checkpoint adoption is permitted after the barrier. Ordinary mutation transactions have no pending snapshot INSERT and pass the barrier normally. A combined insert+invalidate transaction succeeds only if the new snapshot was fully valid before invalidation, including its native pointer, then ends invalidated/erased. A failed barrier rolls back the native mutation too. An AFTER-only hook is insufficient because native rows/hashes may already have changed.

No blanket change to the existing completeness function is needed for old-snapshot status updates. Successor schema still adds reviewed history-edge authorization at NEW consumer insertion and narrow tombstone CHECK branches. Preserve snapshot immutability and content/identity CHECKs; explicitly test valid insert+invalidate, invalid insert+invalidate, invalid insert+erase, ordinary old invalidation and rollback. Atomic closure suppression must be consumed by archive.read/read_range, checkpoint_summary, _capture, mark_sent and adopt. History-source predicates must not weaken original task-native insertion checks.


P1a private memory deletion remains its existing owner-scoped erasure/CAS behavior and never deletes a shared native original because one private consumer was removed. This history slice cannot create private revision dependencies on new shared source kinds; those remain outside activation. A future design4.4 extension may introduce revision dependencies only after separate approval; preserve private inactive/superseded/deleted intent under its existing commands. This proposal does not activate that future graph. Native deletion blocks new history paths even when native citations/evidence retain snapshots. Internal Research evidence/retention ownership remains native/#43, never public read_source.
