### Exact approved metadata delta

- `chat_threads.compaction_revision bigint NOT NULL CHECK (>0)` and `chat_messages.compaction_revision bigint NOT NULL CHECK (>0)`, backed by one dedicated noncycling `chat_compaction_revision_seq` (not owned by a native identity column; ordinary TRUNCATE RESTART IDENTITY must not reset it). - BEFORE INSERT always assigns nextval, ignoring supplied revision. BEFORE UPDATE assigns nextval when any existing mapped field changes; unchanged native values retain OLD.compaction_revision, regardless of a caller's supplied revision. The trigger uses only OLD/NEW comparisons and sequence allocation; it performs no SELECT or UPDATE of another row, no root lock, and no context-pointer update. Sequence gaps/rollback are valid; values are opaque equality tokens, not timestamps, commit order or a business counter. Sequence reset/exhaustion fails safe and is not a supported administrative mutation.

- The sequence prevents delete/reinsert of the same message/thread ID from recreating a captured revision. Source native_version gains the exact message compactionRevision; operation/input manifests pin thread revision and ordered `(message_id,compaction_revision)` membership in addition to exact source hashes/parent/status and covered units. ### Option A native/FK ordering

Actual `chat_messages.thread_id -> chat_threads.id` is nondeferrable; its INSERT/new-thread UPDATE checks acquire a key-share lock on the referenced thread. Actual `SELECT ... FOR UPDATE` on that thread conflicts with that mode. Thus an existing committed insertion is visible to a fresh READ COMMITTED manifest query after root acquisition; a still-in-flight insertion holding its FK lock makes NOWAIT acquisition fail; an insertion whose FK check is later blocks until the compaction transaction ends. The last case serializes after adoption, and the next dispatch must revalidate. This is the specific phantom argument to prove, not an assertion that ordinary source-row locks prevent phantoms.

The command locks **all** currently visible messages belonging to the captured thread (bounded count), not only the compressed prefix; the manifest is scoped metadata, never an invitation to summarize sibling bodies. Those row locks prevent removal, reparent-out and content/status changes during adoption. The root FK guard prevents additions/reparent-in. Under READ COMMITTED, a changed/locked row must produce a full transaction abort or manifest mismatch, never SKIP LOCKED or an incomplete accepted set. A transient insert-and-delete completed entirely between captures, leaving no surviving source/frontier and no changed captured revision, is not presented as a detectable event history; acceptance concerns the exact current ordered context and source set at the linearization point. Mutations of captured rows and active-leaf ABA are detected by revisions.

The deleted parent's child-parent SET NULL and active-leaf SET NULL execute the same **row-local** revision assignment. They acquire no new compaction root/execution lock; the rejected cross-row message trigger is absent. Existing writer deadlocks unrelated to compaction are not claimed repaired. New FKs/retention restrictions must be tested separately from deadlocks; no change to original SET NULL/CASCADE semantics is proposed.

All explicit compactor row acquisitions are NOWAIT; a miss rolls back the entire transaction and releases every guard before at most one fresh retry. No remote call or summary regeneration occurs on retry. Prelock existing FK targets before staged inserts. Constraint triggers validate owner/chain/coverage without taking new root locks after snapshot/call locks. They permit last-good snapshot.context_version <= current owner context_version and require exact new adoption identity at CAS. Option A relies on the native FK behavior; full shipped-schema proof remains required. Local transaction timeout and lock-hold measurements are explicit acceptance data, not an assumed performance pass.
