# Citeframe 记忆管理改造方案

日期：2026-09-28
版本：授权规格 v4（循环内压缩与共享输出边界）
状态：规则已授权；合同与迁移设计经独立审核后实施。

## 1. 改造目标

覆盖普通聊天和 Research，实现：

- 长对话按预算组织上下文，自动压缩较早内容。
- 模型根据需要主动搜索历史、读取原文。
- 跨对话保留项目约束、用户偏好和已确认决定。
- 新信息能够更正、替代旧记忆。
- 记忆有来源、有权限范围，可以查看、修改和删除。
- Research 压缩上下文时保留事实条件、冲突和证据关联。

当前消息、资料、证据和研究记录继续复用，不改变原始记录的含义。

当前已核对的普通聊天路径按父消息关系提取当前分支的已完成历史，直接拼入模型输入；尚未确认该路径具有自动历史摘要或主动历史查询工具。Research 已有任务状态、证据、检查点和结构压缩，但结构压缩不等于语义摘要，也不构成跨任务长期记忆。

## 2. 总体架构

```text
用户消息 / 工具结果 / 研究结果
                ↓
          原始记录持久化
                ↓
       任务摘要与长期记忆提取
                ↓
       来源校验、去重、更新、索引
                ↓
          记忆存储与检索服务
                ↑
                │
当前请求 → 权限与范围 → 上下文组装 → 主 Agent
                                       │
                                       ├── 搜记忆
                                       ├── 搜历史
                                       └── 读原文
```

普通聊天与 Research 共用记忆服务。模型负责语义提取、判断信息缺口及提出查询；程序负责权限、版本、预算、持久化和工具执行。

默认由主 Agent 主动查询。复杂历史调查需要隔离上下文时，再引入独立记忆 Agent。

## 3. 四层记忆

| 层级 | 来源 | 保存与使用方式 |
| --- | --- | --- |
| 近期上下文 | 当前分支最近的完整消息与工具交互 | 从原始记录按 token 预算选取，每轮默认携带 |
| 任务记忆 | 当前目标、约束、执行进度、已确认结论、未解决项 | 按任务和分支保存版本，角色切换及恢复时加载 |
| 长期记忆 | 明确要求记住的信息、稳定偏好、持续有效的事实与决定 | 按作用域、相关性和有效状态召回 |
| 原始档案 | 消息、工具结果、文档、研究证据和产物 | 保存原始内容，通过来源 ID 精确读取 |

### 3.1 近期上下文

由程序从当前分支末端向前选择，不调用模型逐条筛选，也不另行复制一份历史。

选择规则：

1. 当前用户输入和必要系统规则优先保留。
2. 按完整对话单元向前累计 token。
3. 工具调用及其结果保持对应关系。
4. 大工具输出使用有来源的片段或摘要，原文另行保存。
5. 较早且放不下的消息由摘要覆盖，必要时回查。

近期上下文主要维持当前对话的连续性；重要旧信息通过任务记忆、长期记忆和原文检索补充。

### 3.2 任务记忆

采用结构化内容：

```text
目标
已确认约束
执行进度
已确认决定
事实及来源
冲突与未解决项
下一步
```

来源分为两类：程序提供步骤状态、执行结果和产物；模型提取目标、约束、决定和待确认事项。

- 执行状态由现有任务系统维护，摘要引用这些状态。
- 模型提取业务信息，不能自行改写任务的成功或失败状态。
- Research 分支各自更新，汇总阶段合并。
- 每次更新带版本检查，避免并行覆盖。
- 每项重要事实关联来源，恢复时加载对应的记忆和证据版本。

### 3.3 长期记忆

每条记录表达一个范围明确的事实、偏好或决定。并非所有聊天内容都会写入长期记忆。

建议字段：

| 字段 | 含义 |
| --- | --- |
| `id` | 稳定记忆标识 |
| `kind` | 偏好、约束、事实、决定 |
| `content` | 记忆内容 |
| `scope` | 用户、工作区或具体任务／项目范围 |
| `owner_user_id` | 所有者 |
| `visibility` | 私有或明确授权的共享范围 |
| `source_refs` | 来源 ID 与版本 |
| `confirmation` | 用户确认或可验证的工具观察 |
| `status` | 有效、被替代、撤销、过期、来源失效 |
| `supersedes_id` | 被替代的旧记忆 |
| `version` | 并发更新版本 |
| `valid_until` | 可选有效期 |

项目级范围须复用或明确建立项目身份，不能用自由文本项目名作为权限边界。精确类型、必填约束和表结构由合同与迁移设计定义，经独立审核后实施。

示例：

```json
{
  "kind": "project_constraint",
  "content": "项目 X 的正式环境只能部署在内网",
  "scope": "project:X",
  "source_refs": ["message:123"],
  "confirmation": "user_confirmed",
  "status": "active",
  "supersedes_id": null
}
```

每轮召回与当前范围和问题相关的有效记忆。明确设为持续生效的项目约束按范围加载；精确数值、关键决定和冲突需要时回读原文。

### 3.4 原始档案

保留原文、时间、角色、工作区、对话分支、任务和版本信息。

摘要和记忆通过 `source_refs` 指向原始记录。原始内容修改后保留版本关系；删除按保留策略执行，并使相关派生数据失效。

复用现有消息、文档与研究存储，提供统一的来源引用和读取接口。大文件和大工具结果进入对象存储，数据库维护元数据与关联；检索索引关联回原始记录。

## 4. 上下文预算与自动摘要

### 4.1 预算分配

```text
可用输入预算 =
模型上下文容量
－ 输出预留
－ 协议、工具定义等开销
－ 安全余量
```

不同 Provider 按实际上下文规则计算，优先使用对应 tokenizer 或官方计数能力。估算值必须标记，不能统一依赖字符数除以四作为精确依据。

组装优先级：

1. 系统规则、当前请求。
2. 当前目标与已确认约束。
3. 最近连续对话。
4. 相关任务摘要与长期记忆。
5. 检索片段及工具返回内容。

各部分配置软预算，未使用空间允许复用。单条必要输入过大时，明确处理超限，不能静默截断用户问题。按任务类型调整空间分配，例如原话查询为来源读取预留更多空间。

### 4.2 摘要触发

- 较早消息需要移出当前上下文；
- Research 阶段完成；
- 目标、约束或决定发生实质变化。

历史压缩采用“摘要覆盖的旧区间＋未覆盖的近期消息”，记录覆盖边界和分支，避免漏消息或混入其他分支。

### 4.3 摘要生成与校验

生成结构化摘要，保留数字、适用条件、否定结论、冲突和来源。

```text
新增原始内容 + 上一版本任务记忆
              ↓
      生成候选摘要或变更
              ↓
校验来源、范围、版本和关键字段
              ↓
       保存新版本与覆盖边界
```

发生决定变更、冲突或摘要一致性问题时，回读相关原文；必要时从原始区间重建。避免长期只对旧摘要反复摘要。

摘要未通过校验时，不能标记对应历史已被完整覆盖。结构校验不能证明语义没有遗漏，摘要质量仍需固定样例评测。

## 5. 主动记忆检索

### 5.1 工具接口

| 工具 | 输入 | 输出 |
| --- | --- | --- |
| `search_memory` | 查询、记忆类别、允许范围内的过滤条件 | 记忆内容、状态、来源、修订关系 |
| `search_history` | 查询、时间条件、允许的来源类型 | 原始片段、来源 ID、时间和前后文定位 |
| `read_source` | 来源引用、受限的前后文范围 | 原文、版本及来源信息 |

用户身份和可访问范围由服务端注入，模型不能通过工具参数授权自己访问其他范围。

结果统一包含稳定来源引用、内容与时间、有效或被替代状态、截断标记和继续读取所需的标识。

### 5.2 检索流程

```text
权限与作用域过滤
        ↓
关键词 + 向量召回
        ↓
候选去重、相关性重排
        ↓
检查替代关系和后续更正
        ↓
返回片段，按需读取原文
```

明确指定消息 ID 时直接读取。查询“最终决定”时检查更正和替代关系，不能仅以相似度或发布时间排序。

资料检索与聊天历史检索使用明确的来源类型和隔离规则。可复用 PostgreSQL、pgvector 等基础设施，但不能混淆两类内容的权限和业务含义。

### 5.3 调用循环

扩展普通聊天的 Provider 与流式处理链路，支持：

1. 模型返回工具调用；
2. 校验名称和参数；
3. 执行受控查询；
4. 回传对应工具结果；
5. 再次调用模型生成答案或继续检索。

设置每轮工具次数、返回 token、累计调用和时间限制。重复查询无新信息时停止；达到限制后说明剩余缺口。调用、摘要与检索重排的成本均纳入可观测记录，不把当前费用估算描述为精确账单。

## 6. 长期记忆写入与更新

### 6.1 写入流程

```text
明确记忆请求 / 决定确认 / 阶段结果
                ↓
        提取明确授权或可验证信息及出处
                ↓
      权限、敏感内容、来源校验
                ↓
       查询相同范围的已有记忆
                ↓
新增 / 去重 / 补充 / 替代 / 标记冲突
                ↓
          持久化并更新索引
```

明确要求“记住”的请求完成写入后才回复已保存。明确授权或可验证信息的提取可后台执行；未经校验的中间结果不作为长期记忆持久化。近期原始消息继续保留，避免后台延迟造成信息空缺。

### 6.2 更新规则

- 重复信息合并来源，避免重复召回。
- 用户明确更正时，新记录关联并替代旧记录。
- 适用条件不同的内容并存，不能误判为互相替代。
- 不明确的矛盾保留在任务记忆的冲突与未解决项中；含糊的用户属性和意图不写入长期记忆。
- 模型建议不能标记为用户已确认。
- 被替代内容不作为默认有效记忆召回，但可用于解释历史。
- 凭据等不允许保存的敏感内容不写入长期记忆。

并发更新使用版本检查；提取任务使用来源版本和任务标识去重，重试不重复创建记录。

## 7. Research 接入

| 环节 | 使用方式 |
| --- | --- |
| Planner | 加载任务目标、约束和相关有效记忆，生成计划 |
| Researcher | 维护分支查询记录、事实摘要、证据 ID 和缺口，按需读原文 |
| Verifier | 从结论关联的原始证据核验，不只读取上游摘要 |
| Critic／调查 | 保存冲突双方、调查结果、已解决与未解决状态 |
| Synthesizer | 使用已核验结论和未解决项组织报告，需要细节时回读来源 |

历史记忆可以帮助规划，但不能自动成为当前研究的已核验证据。最终报告使用的来源仍须满足本次研究的资料范围和证据契约。

任务恢复绑定记忆、工作流和证据版本。外部模型调用完成但尚未保存的窗口，仍按现有不确定结果机制处理。

研究完成后，仅将有持续价值、范围明确、来源可验证且通过校验的信息写入长期记忆，并保留观察属性。整份报告不自动写为永久事实。

## 8. 权限、删除与用户操作

### 8.1 权限

- 检索、原文读取、写入和工具执行都校验权限。
- 当前分支以外的对话不能自动当作当前已采纳的决定。
- 私有记忆默认不升级为工作区共享内容。
- 历史消息中的指令作为资料处理，不具有当前指令权限。
- 成员被移除后，新读取与执行中的工具访问重新校验。

### 8.2 管理入口

提供记忆列表、来源查看、纠正、停用和删除功能。

- 编辑带 `expected_version`，冲突返回明确错误。
- 编辑产生新版本，保留授权范围内的修订关系。
- 删除立即使记录不可检索，再异步清理向量索引、缓存及派生摘要。
- 清理未完成期间，通过源记录状态和读取校验阻止旧索引返回内容。
- 删除失败保留可恢复的处理状态，不向用户虚报彻底清除。

刷新页面后从服务端读取当前版本。保存失败时保留用户未提交内容并提示恢复方式。撤销或恢复必须遵守数据保留策略；永久删除完成后不提供虚假的恢复能力。

## 9. 模块边界与持久化

### 9.1 模块职责

| 模块 | 负责内容 |
| --- | --- |
| 上下文组装器 | token 预算、消息选择、摘要覆盖 |
| 摘要服务 | 生成、校验、版本化摘要 |
| 记忆写入服务 | 合格信息提取与校验、更新和替代 |
| 检索服务 | 权限范围、召回、重排、来源读取 |
| 工具适配器 | 模型工具协议、循环与限制 |
| 生命周期任务 | 索引更新、删除传播、过期处理 |

共享能力放在中立模块，由 API 和 Worker 调用，避免新增 Worker 对 API 路由实现的依赖。

### 9.2 数据变化

复用现有消息、证据、任务和产物，新增或扩展：

- 任务记忆快照；
- 长期记忆及修订记录；
- 来源关联；
- 检索索引；
- 摘要、提取与删除等处理任务。

现有历史记录保持原样。存量内容可建立检索索引；不自动把所有旧聊天转换成已确认长期记忆。

必要的新增字段、接口请求响应、错误码和迁移步骤已获制定授权；具体合同必须先形成可审计设计并通过独立审核。

## 10. 验收标准

建立聊天与 Research 两套固定测试集，覆盖：

1. 早期信息与精确参数找回；
2. 新决定替代旧决定；
3. 模型建议与用户确认区分；
4. 对话分支、同名项目和工作区隔离；
5. 工具循环、超限、取消和恢复；
6. 摘要保留关键条件与冲突；
7. 删除后的检索及派生内容失效；
8. 检索不到时明确表达不确定。

分别记录回答正确性、来源支持、召回表现、过时记忆误用、延迟与费用。

跨范围泄露、已删除内容仍可读取、静默覆盖记忆、报告引用不支持结论，均作为阻止发布的问题。具体效果阈值在测试集标注和当前基线测量后确定。

页面验收覆盖：持续长对话、主动读回历史、查看来源、纠正记忆、版本冲突、删除、刷新恢复及权限变化后的访问。接口和单元测试不能替代真实用户路径验收。

## 11. 已授权的持久化规则

以下规则约束数据归属及保存合同：

1. 跨对话记忆默认私有；工作区共享记忆需明确共享或由授权角色创建。
2. 只持久化明确要求记住、明确确认的决定／约束／偏好，以及有可验证来源且满足范围规则的信息。含糊的用户属性或意图不写入长期记忆。重要且影响任务时再询问，不每轮弹确认。工具观察保留来源及观察属性，不能标记为用户确认。Research 未解决事实和冲突保留在任务记忆。
3. 删除原始来源后，相关摘要和记忆先失效；有其他有效来源时重新计算。
4. Research 不默认扩大冻结资料范围；历史记忆作为规划参考，作为报告证据需另行纳入允许范围。

必要的新表、API 和迁移可在可审计设计及独立审核后实施。新增共享功能、删除原始档案、扩大证据权限等范围外变更须单独确认。

## 12. 循环内自动上下文压缩与续跑

### 12.1 交付目标与边界

普通聊天与 Research 在同一次任务执行期间自动处理上下文增长：每次主模型请求前检查预算，达到阈值时生成可追溯的压缩检查点，替换下一次请求中对应的旧历史，然后继续原来的任务。用户无需发送新消息、手动触发摘要或重启任务。

此处借鉴自动压缩的使用体验，不承诺复刻 Codex 内部算法或供应商加密压缩格式。长期记忆提取与运行中的上下文压缩为独立机制；取消含糊长期推断不影响保留任务内不确定性。

### 12.2 检查位置与触发策略

统一上下文组装入口覆盖首轮请求、每轮工具返回后的续轮请求、Research 角色切换及任务恢复后的请求。已经流式生成中的请求不在中途替换上下文；检查发生在下一次请求发出前。

模型可用输入额度扣除输出预留、工具定义/协议开销和安全余量。不得把旧的单次输入上限直接当成模型真实上下文容量。Provider/model 计数能力、配置阈值及估算来源需明确记录；未知容量不可随意猜测。

配置自动触发软阈值和压缩后目标水位，目标水位低于触发阈值以避免反复压缩。精确默认值由模型容量、原型样例测量和设计审核确定。只在新增可压缩历史足够时重复压缩；同一历史边界无收益时不循环重试。

### 12.3 内容保留与摘要契约

保留当前用户请求、可信系统规则、明确约束、最近完整对话及工具交互、当前待处理状态。旧历史摘要至少包含目标、约束、已确认决定、已完成工作、失败尝试、关键参数与来源、证据ID、冲突/未知项和下一步。

工具调用及其结果必须组成合法完整单元；并行工具调用的结果未齐备时不得截断成不合法历史。超大工具结果采用持久化原文加受限片段/来源引用，不得伪造或丢失调用关联。摘要内容视作带来源的数据，不能把历史提示注入升级成系统指令。

Research 已核验证据与历史参考保持区分；摘要不得产生新的证据资格。原始消息、日志、证据按既有保留规则存储，不因压缩删除。

### 12.4 检查点与原子切换

压缩检查点记录工作区/用户、对话或run、分支/step、被覆盖消息区间或来源集合与版本、父摘要版本、输入指纹、摘要正文及来源关系、策略/模型/计数版本、压缩前后估算量和状态。精确表字段由数据合同设计确定，优先复用既有任务/版本机制。

流程：读取当前上下文版本→构造候选摘要→校验来源/范围/完整单元及结果→重新计数→原子提交检查点并比较上下文版本→下一轮采用摘要和未覆盖近期内容。

未经成功提交不得推进摘要覆盖边界；并发新消息、分支切换、来源删除和权限变化导致候选过时时拒绝采用或基于新版本重建。重复尝试使用稳定操作身份去重。恢复时加载已提交检查点，未提交摘要不能作为已完成状态。

### 12.5 续跑语义

压缩只改变模型下一轮可见的上下文表示，不改变run/step/attempt身份、已执行工具状态、研究证据范围、累计预算、取消标记或步骤前置条件。不能因压缩重新执行已经完成的工具或重复发布产物。

压缩请求走独立的受限调用路径，避免递归触发自身压缩。输入过大时按完整来源单元分块归纳，再合并并核验关键事实；总调用/时间/资源有界，不允许无限摘要。压缩相关模型调用和消耗纳入账本与可观测记录，不重置现有业务预算或将估算冒充实际账单。候选生成和恢复仍遵循已有外部调用结果未知处理。

### 12.6 失败、取消与失效

摘要失败或无有效压缩收益时，原始上下文及已提交检查点保持不变。原请求仍满足安全硬上限时可继续；无法容纳时进行有界重试或进入明确可恢复错误，不静默截断必要输入、不无限重试、不用空摘要继续。

用户取消时停止后续请求，迟到结果不得推进已取消任务。权限撤销或来源删除后，压缩摘要和检索片段均重新校验，失效检查点不得继续向模型发送已无权读取的内容。

### 12.7 用户体验与可观测性

长任务可显示简短的“正在整理上下文”状态，完成后恢复原任务进度；不要求用户点击继续。页面刷新和断线后状态可恢复。日志/事件记录触发原因、覆盖范围、前后大小、耗时、计数来源和失败原因；日志不泄露原始敏感正文或凭据。

### 12.8 必须通过的验收

1. 单次聊天任务内多轮工具结果使上下文跨过阈值，无新用户消息即可触发压缩，并继续生成最终答案。
2. Research 同一任务中至少两次跨阈值，约束、关键数字、否定条件、未解决冲突和证据关系仍正确保留。
3. 包含并行工具调用、超大工具结果、无可压缩区间以及压缩后仍超限的边界；模型请求结构合法，失败有界。
4. 压缩前后完整业务轨迹对比：已完成副作用工具、报告发布没有重复；预算/调用计数连续，取消状态不丢。
5. 候选生成中、检查点提交前及提交后模拟崩溃，重启后覆盖范围正确，无漏消息/重复覆盖；不宣称外部模型调用严格exactly-once。
6. 分支切换、并发消息/压缩、跨用户/工作区、权限撤销和来源删除均有负向测试，不泄露其他分支或已失效内容。
7. 摘要遗漏关键事实的负向样例必须被质量评测识别；结构校验通过不代表语义无损。固定输入对比准确性/来源支持与压缩收益，分别报告模型质量和工程结果。
8. 真实页面走查自动整理状态、不中断续跑、失败提示与刷新恢复；不能只测数据库新增了摘要行。

## 13. 当前输出边界与私有记忆使用范围

不新增私有对话、私有 Research 模式或原生 audience 列；现有输出权限保持不变。私有记忆可按 owner 隔离存储和用户管理，不在共享对话或 Research 中自动复用。

共享上下文、search_memory/search_history/read_source 工具、摘要、检查点、规划和其他派生链路均不得接收私有内容。当前请求者能读取某条私有数据，不代表可将其发送到共享输出。身份权限与输出受众检查同时成立才可使用来源；已明确共享的内容只按既有授权规则使用，不自动升级私有数据。

共享聊天与 Research 的循环内压缩正常实施，只覆盖本会话/任务合法共享上下文；研究冻结证据范围不扩大。私有记忆列表/来源管理与模型共享检索是分离入口。两个同工作区成员及 owner 必须验证私有标记不出现在共享 prompt、工具结果、流、检查点、摘要、规划、日志和最终产物。
