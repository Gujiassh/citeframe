# 2026-08-03 V5 能力优先路线裁决

## 裁决

Citeframe 后续开发采用 capability-first 顺序：

1. 多模型/provider profile 与 capability contract
2. 多模态资料的逐模态纵向闭环
3. 受控多 Agent 协作产品化
4. 多模型、多模态、多 Agent 的 Workspace 整合与工程稳定
5. R803/后续模型质量评估、M404 真实用户验证、Beta/正式发布判断

## 解释

- V1/V2/V3 PDF/Image 和 V4 R000-R800 是已完成工程基线，不重新实现。
- 质量评估、用户验证和发布证据仍然必须完成，但不再作为前四个能力阶段的前置阻塞。
- R803 formal v1 失败目录保持不可变，不覆盖、不续跑、不根据失败结果推断模型质量；任何后续 provider campaign 使用新目录并遵守独立授权。
- M404 的真实用户门槛、样本协议和 `internal_preview` 规则不降低，只把执行顺序放到功能主线之后。
- V4 `requirements-discovery.md` 的 D001-D007 是当时的批准记录，保留原文；本裁决只改变 V5 的后续执行排序，不改写历史批准事实。

## 合同边界

- 多模型支持可能影响 R000 当前“一次 Run 一组 server-resolved provider/model”的 API、快照、权限、预算、成本和数据边界合同。实现前必须单独形成 V5 contract、迁移影响和审批记录。
- 新模态必须单独定义 modality brief、Representation、ContentUnit、typed locator、retrieval channel、Viewer、删除/恢复和成本边界。
- 多 Agent 复用 V4 的固定 typed executor、Evidence-only tools、HITL 和恢复账本，不扩展为通用 Agent 平台。

## 2026-08-03：DeepSeek generation 第一接入切片

- 采用独立 provider adapter 接入 DeepSeek Anthropic Messages API，不改变现有“一次 Run 一组 server-resolved provider/model”快照、数据库字段、Citation、NoteSource、Chat 或 Research 保存语义。
- 当前配置支持 `generation_provider=openai|deepseek`；DeepSeek 使用 `AI_PDF_DEEPSEEK_API_KEY` 和 `AI_PDF_DEEPSEEK_API_BASE`，默认 base 为 `https://api.deepseek.com`，运行时规范化为 `https://api.deepseek.com/anthropic/v1/messages`。
- 2026-08-03 以官方 `/models` 实测当前可用 ID 为 `deepseek-v4-flash`、`deepseek-v4-pro`；官方价格页标注 Flash 版本为 `DeepSeek-V4-Flash-0731`。这证明接入可用，不等同于最新模型质量或发布验收。
- MockTransport、API 全量回归以及真实同步/流式请求均通过；模型质量评估继续留在 V5-E，不作为本切片的完成条件。
